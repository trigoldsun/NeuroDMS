0开始之前：四个必须知道的概念

不理解这四个词，后面每个页面都会看得别扭。

概念 01

空间：文件的顶层容器

类似"项目盘"。每个人有自己的个人空间；团队空间由管理员或所有者创建。所有文件都在某个空间里，没有例外。

在哪看：左侧空间列表
概念 02

权限档位：对"某一个对象"能做什么

它不是"角色"。同一份文件，你对它是编辑者，对隔壁文件可能只是查看者。判定永远发生在具体对象上。

在哪看：授权抽屉里的五个档位
概念 03

密级：内容本身的敏感等级

公开 → 内部 → 敏感 → 秘密 → 机密 → 绝密 → 核心。它先于权限生效：密级不够，给了权限也打不开。

在哪看：文件属性、上传时选择
概念 04

外链 / 票据：发给组织外的临时通道

链接本身是长期凭证；访客真正取文件时用的是一张 5 分钟票据。所以"链接还在"和"现在还能取到"是两件事。

在哪看：分享抽屉、/s/{token} 页面

五个可用权限档位（从左到右能力递增）

档位能做什么典型给谁
查看者看到、在线预览只读旁听的人
贡献者+ 下载、打印、上传往目录里交材料的人
编辑者+ 在线编辑、复制、改名一起改文档的同事
管理者+ 移动、删除、内部分享、版本管理项目负责人
所有者全部能力，并且可以给别人授权空间 / 文件的负责人

后端另保留了「评论者」档位但界面未开放，当前请用「查看者」。

一条贯穿全系统的规则：能力不够时，系统宁可说"不存在"，也不告诉你"你没权限"。所以你看到 404 很多时候是权限问题，不一定是文件没了。

用「权限解释」（见场景 2）能看清卡在哪一步。

0登录后的第一屏（工作台）

适用 所有登录用户 入口 登录后自动进入 /home；点左上角产品名随时回来

工作台不是"又一个首页"，它按你下一刻要做什么排顺序：待办 → 职责 → 数字 → 最近 → 空间。

区块回答的问题什么时候出现
等你处理有没有事必须由我拍板（移交确认、外发审批）有待办才出现
职责视图作为管理员，我该关注哪些数字有管理角色
关键数字能进几个空间、占多少存储、最近打开过几个有内容或待办
最近打开我上次在弄的那份文件在哪有访问记录
我的空间从哪进、容量还剩多少有可见空间
#谁做什么注意
1所有人先看「等你处理」里面每一条都必须由你处理，别人替不了
2所有人点「最近打开」的卡片直接预览新页签打开；记录来自你自己的审计日志，同事看不到
3所有人点空间卡片进空间根目录卡片上显示所有者与最近更新时间
4管理员「职责视图」的橙色/红色提示优先处理提示的是"资产没人管"（仅所有者可达 / 孤儿空间），不是"文件多不多"

管理员的工作台空间数是 0，这是设计不是故障。管理角色管配置，不自动获得内容权限； 工作台会用一行说明代替一排 0。要查看某个空间，需要所有者授权。

1把文件存进来

适用 贡献者及以上 入口 空间 → 目标目录 → 上传 / 拖拽
#谁做什么注意
1提交人进入目标目录再上传上传落在当前目录。在根目录上传想放进子文件夹，需要先双击进目录
2系统选完文件的瞬间校验格式不合规会立刻标红并不入队。这是租户管理员配的白名单，改不了就找管理员
3系统大于 2MB 先算 SHA-256这一步没有网络流量，只显示「校验 x%」。不是卡住，大文件可能要几十秒
4系统命中相同内容即"秒传"同一份文件第二次上传几乎瞬时完成，且不重复占容量
5系统分片上传，每片 1MB进度按"片完成"推进。1MB 在慢速上行下约 10 秒一格，数字不动就是真的没在动
6提交人中断后重新选择同一个文件服务端按"内容 + 目标目录 + 文件名"复用 24 小时内的会话。改文件名会变成新会话，等于从头传
7提交人需要停掉时点「取消」取消不会删服务端已收的分片，重选同一文件可续传

三个常见误会

"上传完但列表里看不到"

多数是同名文件被覆盖成了新版本。点该文件 → 版本 → 看有没有 v2。系统对同名文件是追加版本，不是产生两个条目。

"别人上传同名的，把我的覆盖了"

同上。旧内容在历史版本里，可回退（见场景 4）。

"提示超过 20MB 不让传"

这不是系统的硬限制，而是租户策略 maxUploadMB。管理员可调，见管理手册 §3.2。

2找到一份记不清名字的文件

适用 所有登录用户 入口 顶部搜索框 / 空间内逐级浏览
#谁做什么注意
1用户输入文件名片段即可只搜文件名，不搜正文内容。正文检索不在当前版本能力内
2系统逐条判可见性所以"搜不到"可能是没权限，不是不存在。换一个有权限的账号试试能确认
3用户点文件名在列表里点文件名＝点「预览」，新开页签，不打断当前列表
4用户空间名可点点工具栏上的空间名，直接回到该空间根目录，不用逐级退
5用户拿不准为什么打不开用「权限解释」看分步结论（见下）

权限解释怎么读

判定按固定顺序执行，卡在哪一步会明说：

租户→ 主体有效→ 对象存在→ 密级→ 显式拒绝→ 允许集合→ 条件→ 结果
结论真实含义该找谁
TENANT_MISMATCH链接或账号属于另一个租户确认登录的租户是否正确
SESSION_INVALID会话被吊销（改密 / 停用 / 登出）重新登录
CLASSIFICATION_DENIED你的密级低于文件密级安全管理员调整密级或申请人
EXPLICIT_DENY有一条明确的拒绝条目对象所有者
NO_ALLOW没有任何条目给你这个权限所有者授权
CONDITION_NOT_MET条件不满足（如要求 MFA、指定网段）按条件补齐

3和同事一起看 / 改一份文件

适用 所有者（授权）、被授权人（协作） 入口 文件行右侧「授权」/ 分享抽屉里的「内部分享」
#谁做什么注意
1所有者授权时优先选部门 / 角色 / 组给组授权一次，比给十个人各授一次更好维护；人员变动自动生效
2所有者授权可设到期时间临时协作建议设到期，避免"忘了收回"
3所有者需要"这个子目录例外"时断开继承断开后会生成祖先条目的快照。快照不能单独删，要先恢复继承
4所有者撤销授权不能移除最后一个所有者——否则对象会变成没人能管
5被授权人权限变更后刷新页面权限是每次请求实时判定的，不需要重新登录
6所有人部门授权含下级部门给"研发部"授权，研发部下面所有子部门成员都会被覆盖到

内部分享 vs 直接授权

两者最终都落到同一张权限表，区别只是入口：内部分享是"按档位批量授给一批人"的快捷方式，不产生链接。

能内部分享 ≠ 能外发：前者要 share_internal（管理者档位起），后者要 share_external（仅所有者）。

4在线编辑与版本回退

适用 编辑者及以上（编辑）、管理者及以上（版本管理） 入口 文件行「编辑」、版本抽屉
#谁做什么注意
1编辑者首次打开编辑器要等 5~15 秒加载链路是"签发配置 → 下载组件 → 文档服务打开文档"，页面会显示已等待秒数
2编辑者长文档编辑期间不要关页面关掉后会话 10 分钟过期，别人就能回退；重新打开即续上
3管理者回退前确认没人在编辑抽屉会提示"N 个编辑会话进行中"。强行回退会覆盖对方保存的内容，所以系统直接拒绝
4管理者回退后告诉同事回退是追加新版本，不是"时间倒流"：对方手里的旧页面再保存仍会产生更新的版本
5管理者历史版本可单独下载下载历史版本同样需要 download 权限，只有预览权限的人下不了

为什么回退不是"删除后面的版本"：审计要求"任何时刻的内容都可追溯"。删版本等于销毁证据，所以回退永远向前追加。

5把文件发给组织外的人

适用 所有者（发起）、有管理权限的同事（审批）、外部访客（接收） 入口 文件行「分享」→ 生成链接；访客打开 /s/{token}
#谁做什么注意
1所有者优先设有效期不带有效期的链接等于永久开放。默认建议 7 天
2所有者只读交付就关掉「允许下载」关闭后访客能在浏览器里看，但下不了原文件；Office 类会转成 PDF 展示
3所有者涉密内容打开「水印」水印上带"链接 + 来源网段 + 时间"，截图外流时可定位到具体那条链接
4所有者需要知道"是谁在看"就开「邮箱验证」访客必须收验证码才能进。可配邮箱白名单，限定只发给某些域名
5所有者口令要另行走一条通道告诉对方系统不会把口令写进邮件。链接和口令同在一封邮件里，等于没有口令
6有管理权限的同事审批待审批的外链高密级（默认「秘密」及以上）自动进审批。审批人必须同时满足：对该文件有管理权限、密级不低于文件、不是发起人。入口在「管理台 → 外发审批」
7访客打开链接后 5 分钟内有效票据过期刷新页面即可重新兑换，不需要重新找分享人要链接
8所有者撤销后立即生效撤销会连带吊销所有已发出的票据。已经下载到本地的文件收不回来——这是所有方案的共同边界
9所有者换设备 / 换网络可能被拒票据绑定来源网段（IPv4 /24、IPv6 /64）。同一办公网内换电脑没问题，换到 4G 网络需要重新打开链接

空间级外链的额外限制

对"整个空间"生成外链时，系统会先检查空间内有没有你自己也看不到的内容：

  • 有更高密级的文件 → 拒绝，提示改为分享具体文件 / 目录；
  • 有显式拒绝的条目（说明子树里做过例外配置）→ 同样拒绝。

这不是刁难：空间级外链等于把整棵子树开放给匿名访客，一旦里面有例外，就会绕过那条例外。正确做法是改为分享具体文件 / 目录，而不是让管理员去删例外配置。

审批：谁批、在哪批、没人能批怎么办

密级达到租户阈值（默认「秘密」）时，链接自动进审批——不需要你勾任何选项，界面也不会问你"选谁审批"。审批人由权限决定，不由发起人指派：如果可以自己挑，谁都会挑最容易通过的那个。

审批人必须同时满足三个条件：

条件 1

对该文件有管理权限

空间「管理者」或「所有者」档位，或在文件上单独授过管理权限。

条件 2

密级不低于该文件

密级先于权限：看不到的文件批不了。

条件 3

不是发起人

系统不允许自批，会提示"请由他人复核"。

在哪批：管理台 →「外发审批」（/admin/share-approvals）。列表只显示"你有权处置"的链接，所以不会出现看到了却点不动的情况。通过后链接立即可用，不用重新创建。

管理角色不等于审批权：系统管理员、安全管理员管的是配置，不自动获得文件的内容权限。所以"我是管理员为什么看不到待审批"是正常现象——缺的是对象级管理权限，不是角色。

没人能批怎么办

会发生在权限集中在一个人手里的空间（个人项目、单人负责的目录很常见）：

  1. 创建时若系统判断"没有其他人能审批"，分享面板会直接亮黄条提示（接口返回 approverCount = 0）；
  2. 解决方式：到「文件 → 该空间 → 权限」给一位同事授「管理者」，并确认他的密级不低于这份文件；
  3. 或者把文件密级降到阈值以下（走降密审批），之后新建的链接不再需要审批——已经 pending 的链接不会自动放行，需要重建。

没有通知：待审批不会主动提醒任何人。需要线下约定"谁每天看一次外发审批"，或者把审批人拉进交付流程。

6查看各种格式的文件

适用 查看者及以上 入口 点文件名，或文件行「预览」

点文件名＝点预览。不同格式走的路径不一样，先用一张图记住"哪类慢、哪类不能看"：

PDF / 图片 / 文本立即打开

浏览器直接显示，可缩放、翻页。

没有任何等待，也没有转换环节。

Word / Excel / PPT首次 3~15 秒

服务端转 PDF 后显示，页面会显示「正在转换」与已等待秒数。

只有首次慢，之后是百毫秒级。转换器未就绪时提示"请下载后查看"。

HEIC（iPhone 照片）10~20 秒

在浏览器内用 wasm 解码，期间页面不卡但图未出。

超过 6000 万像素会提示下载。每次打开都要解码，不是缓存问题。

相机 RAW（CR2 / NEF / DNG 等）首次 3~15 秒

有内嵌预览图的机型先出图，后台再渲染高清版。

索尼 ARW、佳能 CR3 未做完整验证；失败时会提示下载，不会误报成功。

视频后台转码

转码未完成时接口返回"准备中"，前端轮询，就绪后秒开。

没有进度百分比，只能轮询，大视频请提前转。

压缩包 / 邮件 / CAD / HTML只能下载

不在预览范围内，点开只有下载入口。

HTML 刻意不给在线渲染——同源渲染有安全风险。

"为什么这个格式不能预览"：管理台「系统设置 → 允许上传的格式」里，每个格式右侧有徽标：可预览 / 可预览 · 转码 / 不可预览。徽标由服务端按当前实例能力计算，不是写死的。

7账号、密码与工作交接

适用 所有用户（自助）、系统管理员（管理他人） 入口 右上角账号菜单、管理台「成员与角色」
#谁做什么注意
1用户改密码后所有设备会被踢下线这是有意的：账号被盗时，改密必须能收回已有凭证
2用户连续输错 5 次会被锁 30 分钟锁定按账号计，不是按 IP。锁定期内即使密码正确也拒绝
3管理员停用/删除前系统强制检查名下空间只要他还拥有空间，操作被直接拒绝并列出空间名。这是硬约束：停用后他登不进来，空间就没人管了
4管理员被拒后先去「空间台账」移交移交完成再停用即可通过；不想移交就不能停用
5管理员只是账号被盗要立刻踢下线用重置口令：立即吊销全部会话，但账号仍可登录，不会让空间失去负责人
6管理员停用立即生效、删除是软删除令牌在 30 秒内失效；软删除保留 30 天，期间审计与回收站仍可追溯
6用户外部协作者默认强制二次验证外部账号创建时 mfa_required 自动为真，收不到验证码则无法登录（fail-closed）

7.2 空间移交：谁能发起、怎么生效

发起人接收人生效方式为什么这样定
当前所有者任意可用成员立即生效自己的东西自己处置
系统管理员（非所有者）第三方立即生效，审计记发起人代离职/离岗人员交接，不存在利益冲突
系统管理员（非所有者）自己原所有者 7 天内点同意才生效管理员能看到所有账号，不设闸就能把任何人的空间收进自己名下
#谁做什么注意
1所有者文件页标题右侧点「移交」，选接收人接收人必须本租户可登录，且密级不低于空间密级
2所有者移交后自己不再是所有者不可撤销；对方可以再移交给别人
3管理员管理台「空间台账」对任一空间点「移交」转第三方立即生效；转给自己会生成待确认请求
4原所有者在工作台「等你处理」点同意或拒绝7 天不处理自动失效；拒绝后对方要重新发起
5管理员原所有者已停用/删除时不能转给自己（没人能确认），只能转给第三方

一次移交同时改三处：空间归谁、空间里原属于他的文件归谁、谁能管理这个空间。 只改前两处会出现"名字换了、权限没换"，所以三者在一笔事务里完成。
