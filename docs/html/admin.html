1开始之前：三个管理角色的边界

角色能进哪些页签关键边界
系统管理员 sysadmin 概览、成员与角色、操作日志、系统设置、目录认证 看不到文件内容；改不了密级与审计
安全管理员 secadmin 密级定义、标签策略、降密审批、操作日志 建不了号、改不了系统参数
审计管理员 auditor 审计日志（只读） 任何写操作都不可用

三者的冲突组合（如 sysadmin + auditor）会被运行期拒绝：持有冲突角色的账号，所有管理接口返回 403 并写审计。详见《角色能力》§5。

管理台地址：/admin/{tab}。页签按角色动态渲染，地址与页签一一对应，可直接收藏或转发给同角色同事。

2.1 部门树

入口：管理台 → 部门。

部门不只是"成员的一个属性"，它同时是授权的载体：在文件或空间的「共享」里可以按部门授权，命中范围是整棵子树。所以"组织架构建对了，权限就少配一半"。

操作规则
新建选上级部门；同级不能重名（不区分大小写）。顶层部门随开通自动创建（「总部」）
改名只改显示名，路径不变；已授出的权限继续有效
移动连同整棵子树一起走；不能移动到自己的下级（会成环，直接拒绝）
删除有子部门、成员或空间时不允许删除，提示里给出数量；根部门不能删
目录同步来的部门标有「目录」，界面不提供改名/移动/删除——请在 AD / LDAP 里改

为什么删除不级联：级联删除会把"某些人的部门"悄悄改掉，事后没人说得清是谁动的手。系统宁可拒绝，让你先把人挪走再删。

两个常见场景：

  • 只想给某个组看一份文件 → 先建「财务部」并把 3 个人放进去，然后在文件共享里授给「财务部」，以后来新人只要入到该部门就自动能看到；
  • 公司调整组织架构 → 直接把「研发部」移到别的部门下，子树里的成员与已授权限一起跟着走，不需要逐个重配。

目录同步与手工建部门共存：两者共用一棵树。手工建的部门可以移动到同步来的部门下；但如果 AD 里改了该部门的层级，下次同步会以目录为准。审计会记录每次建/改/移/删（admin.dept.*，含改前改后）。

外部协作者：创建时 mfa_required 自动为真，必须有可用邮箱，否则登不上（fail-closed）。

3系统设置：每个参数的真实含义

入口：管理台 → 系统设置。以下 5 个参数写入即生效，不需要重启。

3.1 外链默认有效期 shareDefaultExpireDays

外链默认有效期shareDefaultExpireDays默认 7
含义
创建外链时建议的默认天数
取值
0 = 不过期；正整数 = 天数
影响
只影响新建链接的默认值。存量链接的策略在创建时已快照，改这个不会让已发出的链接提前失效
建议
保持 7。设为 0（永久）会让链接变成长期敞口，且撤销依赖人工记得

3.2 单文件上传上限 maxUploadMB

单文件上传上限maxUploadMB默认按档位
含义
单个文件允许的最大体积
取值
0 = 按档位默认；正整数 = MB
默认
按档位：基础 1024 / 专业 5120 / 商业 10240
影响
超过即拒绝（413），分片上传的每个分片不受此限制，整体仍受此限制
注意
调大之前先确认磁盘余量与备份窗口。10GB 的单文件会让备份与迁移成本上一个台阶

3.3 日志保留期 auditRetentionDays

日志保留期auditRetentionDays默认 730
含义
操作日志与审计事件的保留天数，决定清理任务删到哪一天
取值
30 ~ 3650；0 落成 730
影响
缩短后不可恢复。删除的是已被日结锚点覆盖的数据，锚点仍能证明"那段时间存在过"，但明细没了
建议
合规场景按监管要求设（常见 180 天 / 2 年 / 10 年三档）。缩短前先导出

3.4 上传超时 uploadTimeoutSeconds

上传超时uploadTimeoutSeconds默认 300
含义
单个上传请求允许的最长读取时长
取值
60 ~ 3600；0 落成 300
影响
约束的是每一片，不是整个文件。片大小 1MB，250Kbps 上行约 32 秒/片，300 秒余量充足
调小
移动网络下大文件会频繁中断。中断可续传，但用户体感差
调大
慢速连接会长期占用一个连接。防大包靠 maxUploadMB 与配额，不靠这个值

历史教训：这个值曾经写死 60 秒，导致 iPhone 照片（4MB）在慢速上行下必然失败，而错误却显示"请使用 multipart/form-data"，把人引向格式问题。现在按租户可配，且超时会明确提示"可重试，大文件会从断点继续"。

3.5 允许上传的格式 allowedExts

允许上传的格式（白名单）allowedExts默认不限制
含义
白名单，小写带点（如 .pdf）
取值
null = 不限制；数组 = 只允许这些
生效点
前端选完文件的一瞬间判一次（不合规直接标红、不入队）；后端单文件与分片初始化各判一次（415）
界面
8 个分组共 101 种格式，支持组内全选、一键不限；每个格式右侧标 可预览 / 可预览 · 转码 / 不可预览
重要
这是入口约束，不是安全边界。危险扩展名与可执行魔数另有独立拦截，两者不可互相替代

徽标由服务端按当前实例真实能力计算（LibreOffice 是否就绪、转码是否启用）。如果某台部署没装转换器，Office 格式会自动变成"不可预览"——不会给你一个必然失败的承诺。

3.7 邮件服务：SMTP / Exchange Online

入口：管理台 → 邮件服务（与「系统设置」「目录认证」并列，仅系统管理员）。验证码、外发分享邮件、审批提醒都靠这条通道，此前只能靠环境变量 DOCVAULT_SMTP_* / DOCVAULT_GRAPH_* 配置，改一次要动 .env 并重建容器。

模式适用关键参数
跟随平台默认小客户、试用；由部署方在环境变量里配好—
SMTP 服务器企业邮箱、内网中继、自建 Postfix主机、端口、加密方式、账号口令、发件地址
Exchange Online / M365用 Microsoft 365 邮箱发信目录（租户）ID、应用（客户端）ID、客户端密钥、发件邮箱

M365 邮箱不要用「SMTP 服务器」+ 邮箱口令。微软已对 Exchange Online 的 SMTP AUTH 基本认证排定停用：2026 年 12 月底起对存量租户默认关闭（可临时重新开启），2026 年 12 月之后新建租户不再提供该选项。失败是静默的——邮件只是不到，不报错给用户。正确做法是走 Microsoft Graph 的 sendMail（应用权限 Mail.Send）：Entra ID 注册应用 → 添加应用权限 → 管理员同意 → 新建客户端密钥 → 四个参数填进本页。21Vianet 运营的 M365 在「高级」里把端点改为 login.chinacloudapi.cn 与 microsoftgraph.chinacloudapi.cn。

口令与密钥：只写不读（输入框留空提交 = 不修改），落库为密文且 AAD 绑定租户与用途；服务端未配置 DOCVAULT_SECRET_KEY 时拒绝保存口令（NO_SECRET_KEY），不会降级成明文，但地址端口等非敏感项仍可保存。

发件人显示名：不填时默认 【系统名称文档管理系统】（系统名称在 3.8 改）。页面上会实时显示"收件人实际看到的名字"。此前 From 头只有邮箱地址，收件人看到的是 noreply@...，既不像系统通知也容易进垃圾箱。

发送测试：用表单当前参数真发一封，不必先保存。结果写在按钮下方并记入「上次测试」。收不到时按顺序查：垃圾箱与 SPF/DKIM → 端口与加密方式是否匹配（587/STARTTLS、465/隐式 TLS）→ Graph 是否完成管理员同意（未同意返回 403 Authorization_RequestDenied）→ 服务器能否出网。

队列：页面底部汇总最近 7 天（24h 已发 / 待发 / 失败待重试 / 已终止）与最近 5 条失败原因。失败按 30 秒 → 1 分 → 2 分 → 4 分 → 8 分重试，5 次后进入「已终止」；修好配置后待重试的会自己发出，已终止的需要重新触发业务动作（例如再点一次"发送邮件"）。

边界：本页配的是本租户的通道，平台默认仍由运维用环境变量维护；开启独立通道后不做回退——租户通道失败就是失败，不会偷用平台邮箱代发（否则邮件从意料之外的域名发出，既难排查也像钓鱼）。「允许明文连接」只在带口令时强制勾选确认。

字段作用限制

上传图标：点「选择图片」→ 选好后立刻能看到读到的真实尺寸与体积（例如 128×128 · 48 KB），确认无误再点「保存名称与品牌」。

项要求

体积不超过 256KB
安全SVG 里不能含脚本或事件属性（会渲染到未登录的登录页，出于安全直接拒绝）

  • 图标会同时出现在登录页与分享页，外部访客也能看到，请确认可以用作品牌标识。
  • 移除图标后立即回退为系统内置图形，不会留空。
  • 只改名称不会影响已上传的图标；更换与移除分别记 logoChanged / logoRemoved 进审计。

浏览器标签页图标（favicon）

同一个图标会自动用作浏览器标签页、收藏夹、手机「添加到主屏幕」的图标，不用单独上传，也没有额外开关。

哪里用租户图标、哪里用产品图标（V1.7.2 起明确）

场景标签页图标说明
登录页 /login产品图标（固定）面向"还没证明身份"的人；这里挂客户标识会让人以为已经进了系统
登录后站内页面当前租户图标侧栏、文件页、管理台等全部一致
外部分享页 /s/{token}产品图标（固定）访客未登录；页眉仍显示租户图标（那是内容品牌）
平台运营控制台 /platform产品图标（固定）平台侧不跟随任何租户品牌
登录态失效 / 主动退出立即回退产品图标不等页面跳转，标签页不会停在客户图标上
未上传图标 / 读取失败回退产品图标深绿底 + 白色 N

一句话：标签页图标表示"我现在是谁的会话"——没有有效会话时，只能显示产品本身。同一台电脑先后登录两家组织时图标会跟着换；多个标签页分别登录不同组织时，各标签页显示各自的图标（图标属于页面）。

边界：浏览器的标签页图标缓存比普通页面顽固得多。Chrome 把图标存在自己的数据库里，换图后已经打开的老标签页可能仍显示旧图，清空站点缓存也未必立刻更新——刷新页面或关掉标签页重开通常就好。这是浏览器行为，不是配置没生效；验证请新开一个标签页或用无痕窗口。

  • 没上传图标时，标签页用系统内置图形（深绿底 + 白色 N）。
  • 手机主屏图标只认 PNG：用 JPEG / WebP / SVG 时主屏回落为系统内置图标。
  • 平台运营控制台（/platform）固定用系统内置图标，不跟随租户品牌。

3.9 文件夹上传（增值功能）

入口：管理台 → 系统设置 → 上传与协作 → 「文件夹上传」。

项说明
能力要求专业版及以上（基础版勾不上，也保存不了生效）
默认关闭。升级后不会"悄悄多出一个批量入口"
打开后文件页右上角出现「文件夹」，也可以直接把目录拖进来
实际效果保留目录层级、自动建目录、同名目录复用、逐文件上传

为什么默认关闭：它是一次能在几分钟内创建上千个目录与文件的批量写入口——配额、预览转码队列、审计量会同时被拉起来。是否开放应由客户自己决定，而不是升级后被动生效。

两把锁，缺一不可：① 档位 edition.Spec.FolderUpload（基础版 false，专业版/商业版 true）；② 租户开关 tenant_config.policy.folderUpload。

判定在写入口生效，不只是把按钮藏起来：预检接口与两个上传接口（小文件一次性、大文件分片）都校验；脚本直接调接口带 folderUpload: true 也会被拒（403 FEATURE_NOT_ENABLED）。关掉功能时，正在传的批次不受影响，新批次进不来。

预检：上传前的那份清单　选了目录后，前端把文件名、大小、相对路径一次性交给 POST /v1/uploads/preflight，服务端按三套规则算出"哪些会被拒"：

原因码触发条件能否靠改配置放开
ext扩展名不在「允许上传的格式」白名单内✅ 改白名单即可
size超过单文件上限（档位与租户策略取小）✅ 调大上限
dangerous文件名中段含 .php/.exe/.js/.sh 等（shell.php.jpg）❌ 硬拦截
name文件名为空 / 超长❌

为什么不放在前端算：三套规则在前端复制一份，早晚与后端不一致——用户看到"通过"，传到一半才被拒，比一开始就说清楚更糟。

跳过语义（必须对客户讲清）

  • 确认「跳过 N 个，上传 M 个」后只上传 M 个；
  • 被跳过文件所在目录，如果没有任何可上传文件，就不会被创建（不留空目录）；
  • 同名目录复用（ALREADY_EXISTS 时按名字找回来），"重传一次"不会报错也不产生重复目录；
  • 一次最多 5000 个文件（TOO_MANY_FILES）；目录逐个创建，几百个时会显示「正在创建目录 x/y」——正常，不是卡死。

3.11 口令规则与二次输入

长度：至少 8 位字符（不是字节）。中文与空格都算一个字符：「文档中心密码」是 6 个字，不合格；「文档中心密码2026」是 10 个字，合格。

入口谁在设置校验位置
成员新建 / 管理员重置管理员internal/iam
开通租户的管理员初始口令平台运营internal/tenant
平台账号新建 / 重置平台运营internal/platformauth
用户自助改密（账户抽屉）本人internal/auth

四处读同一个常量 internal/password.MinLength：改长度只改一处，不会出现"管理员建号能过、用户自己改密过不去"。

掩码：所有口令输入框都以 * 显示，且没有"显示口令"按钮。输入、删除、粘贴、输入法上屏都是掩码。这是刻意的：明文口令在共享屏幕、截图、录屏时会被完整记录，风险高于"看不见自己输了什么"。

二次输入：设置或重置口令时全部要求连续输入两次。两次不一致时输入框下方立刻红字提示「两次输入的口令不一致」，不会提交。管理员给成员设的初始口令，交付后应让本人第一次登录就改掉——管理员知道的口令不算秘密。

边界（务必知道）

  • 老口令不受影响：长度只在"设置新口令"时校验，不会因为规则变化把已登录的人踢出去。
  • 管理员重置仍是人工传递：系统不会给成员发"你的新口令是 xxx"的邮件，请电话或当面告知。
  • 服务端仍是权威：界面校验只是少一次往返；绕过页面直接调接口，服务端同样拒绝短于 8 位的口令。
  • 粘贴是允许的：拦粘贴会让密码管理器失效，反而促使人们用更短更好记的口令。

3.12 短信通道（集成与凭证）

入口：管理台 → 集成与凭证（仅系统管理员）。这一页管"短信从哪家出去"：加密保存厂商凭证、真实测一次连通性、失败时告诉你在哪一环。

短信登录要同时满足三层：授权（平台/档位）、租户开关（系统设置 → 登录方式）、通道就绪（本页）。任一层不满足，登录页不会出现短信入口。

通道核验在哪说明
阿里云短信认证服务云端验证码由阿里云生成与核验，本地不存码；核验接口免费
腾讯云短信本地本系统生成 6 位码，5 分钟有效，最多试 5 次

失败提示：密钥无效 / 模板不存在 / 签名未报备 / 余额不足 / 网络不可达 / 其它（详情记服务端日志，不含密钥）。按提示回厂商控制台对应项核对。

3.13 自定义域名与证书

入口：管理台 → 域名与证书（仅系统管理员）。绑定自有域名是为了让客户看到的链接显示成你自己的品牌。

两件独立的事：绑定域名让地址被解析到本系统；准备证书让浏览器不报警。域名绑好不等于能用。

第 1 步：证明域名归你：填域名（只填主机名）→ 系统给出一条 TXT 记录（_docvault-challenge.<域名>）→ 到 DNS 服务商添加 → 等 1–10 分钟后点「验证归属」。不验证的话，任何人都能把别人的域名绑到自己这里。

第 2 步：准备证书（三选一）

方式适用谁续期
自动签发域名直接解析到本服务器，且 80 端口对外开放系统自动（到期前 30 天）
上传证书已有证书（公司 CA、云厂商、其它工具签的）你自己，系统不会碰
上游代理托管前面有 Nginx / Cloudflare 等终止了 HTTPS上游负责

自动签发的三种模式：关闭（走隧道或反向代理时最常见，界面会说明证书该由边缘托管，不给点了必然失败的按钮）；HTTP-01 自动（域名直连本机、80 可达）；DNS-01 手动（任何形态可用，每次要手工加一条 TXT，不会自动续期）。

证书优先级：你上传的证书优先——一旦手工上传，系统就不再对该域名自动续期。

签发失败会限流，别连点：CA 对"同一域名每小时失败 5 次"有硬限制，超过后该域名一小时内连申请都提交不了。界面在失败后 60 秒内不允许再次点击。调通阶段建议让部署方把 DOCVAULT_ACME_DIRECTORY 设成测试目录（页面会标注），配额宽松、证书不被信任，走通后再切生产。

常见失败：未找到匹配的 TXT（记录未生效/记录名错/同名多条）；DNS 查询失败（服务器不能解析外网）；挑战端口启动失败（80 被占用）；域名校验未通过（DNS 未指向本机或 80 被防火墙拦）；证书不覆盖域名；证书已过期。

  • 一个域名一张证书：通配符证书请走手工上传。
  • 解绑会连带删除证书，该地址立刻无法访问。
  • 降档后已绑定的域名不会被自动删除，但不能再新增；仍可解绑。
  • 私钥加密保存，保存后界面不再显示，也不进审计日志。

  • 建号与改号时，成员密级不能高于操作者本人，服务端强制（CEILING_EXCEEDED）；
  • 重置口令同样受这条限制：低密级管理员不能重置高密级账号的口令——否则他改口令、用对方身份登录，等于绕过上一条（此前只拦了建号，等于控制只做了一半）；
  • 管理员不能提升自己的密级。需要更高密级的账号时，由同级或更高密级的管理员创建；

  • 租户里无人具备所需密级、或客户管理员已失联：由运维用 tenantpass -setclass（§11.6）处理，改密级与写审计在同一事务，输出留档。

4.2 密级的两个作用点

作用点 1

准入：强制访问控制

用户密级 < 文件密级 → 一律拒绝，与 ACL 无关。这是强制访问控制（MAC），先于权限判定。

作用点 2

外发上界：按创建时的快照

外链取内容时校验 节点密级 ≤ 发起人创建时的密级快照。所以"先分享再提密"不能绕过。

4.3 标签策略

给带某标签的文件设一个最低密级下限。效果是"只收紧，不放松"：文件可以比下限更高，不能更低。

用途：让分类 / 打标流程自动兜住密级，避免依赖人工每次记得选。

4.4 降密

普通用户不能直接把密级改低（会返回 NEED_APPROVAL）。流程是：

用户在文件上提交降密申请→ 安全管理员在「降密审批」通过 / 驳回→ 通过后密级下调

升密不需要审批（收紧方向不设障）。

4.5 「外发需所有者确认」：按密级配置

这条规则原本写死在代码里（5、6 级外发时，第一层审批人若不是空间所有者，还要所有者确认）。不同租户的密级语义差别很大——有的把 4 级当"绝密"用，有的 5 级只是"内部机密"——写死阈值的结果是一头管不住、一头说不清。现在改为在密级定义页逐级勾选。

配置效果
勾选该密级外发时，第一层审批人若不是空间所有者，还要所有者确认（第二层）
不勾选只走第一层审批（若密级达到"必须审批"阈值）
缺省与旧行为一致：5、6 级勾选，其余不勾选（升级瞬间线上行为不变）
  • 勾选即意味着必须审批：即使密级低于"必须审批"阈值，也会进入审批流程——否则会出现"要所有者确认、却没有人先批"的自相矛盾状态；
  • 规则不追溯：已发起或已审批的分享按创建时的指派关系与阶段执行。收紧不会让老链接突然多一层，放宽也不会让老链接被放行；
  • 发起人本人是所有者时跳过第二层：否则会变成自批；多个所有者时由发起人选择一位。

5.2 SSO 断言（反向代理注入头）

项要求
共享密钥必填。只靠来源网段不够：同一 docker 网络里任何容器都能发请求
可信网段必填，且拒绝 0.0.0.0/0（等于信任全世界）
断言头可自定义，但禁止用 Authorization、Cookie、X-Forwarded-For 这类客户端可控的头
判定依据用TCP 直连对端判断是否受信代理，不用改写后的客户端 IP

配错任一项，Enabled=false 并带原因，接口自然不可用（fail-closed），不会出现"配错但还在跑"。

5.3 客户端 IP 与可信代理

外链 IP 白名单、票据绑定、审计里的来源 IP、水印页脚，全都依赖"真实客户端 IP"。

必须配置 DOCVAULT_TRUST_PROXY_CIDRS 为你的反向代理 / 隧道出口网段。不配时系统一律使用 TCP 对端地址——如果前面有代理，所有访问会看起来来自同一个内网 IP，后果是：

  • 外链 IP 白名单要么全拦、要么全放；
  • 审计里的 IP 失去取证价值；
  • 水印上的 IP 是错的。

这不是理论风险：审计里如果出现大量同一个 172.x 地址，就是这个配置没做对。

6空间台账与所有权移交

空间的可达性靠授权条目。如果某个空间只有所有者本人的一条授权，那么这个人一停用或离职， 空间就再也没人能打开——管理员也看不到它，因为管理角色不具备内容权限。 所以系统对"停用/删除账号"设了硬约束，并提供专门的移交入口。

6.1 停用或删除前：系统强制检查名下空间

操作有空间时的结果说明
停用账号409 OWNS_SPACES，返回空间清单账号状态不变；清单带"是否仅他可达"标记
删除账号同上删除没有继任者参数，直接删会制造孤儿空间
重置口令不受影响账号被盗时的应急手段：立即吊销会话，不让空间失去负责人

检查在同一事务内、对空间行加锁之后执行。不加锁时，另一笔事务可以在"检查通过" 和"停用生效"之间给他新建一个空间，检查就白做了。

界面表现：成员页点「停用」会弹出清单，逐条列出空间名与"仅他可达"，并给两个出口—— 「去空间台账移交」和「改用重置口令」。

6.2 三种移交组合

发起人接收人生效方式审计
空间当前所有者任意可用成员立即生效space.transfer mode=owner
系统管理员（非所有者）第三方立即生效space.transfer mode=admin
系统管理员（非所有者）自己生成待确认请求，原所有者 7 天内同意后生效space.transfer.request + .approve

为什么"转给自己"要别人同意：管理员能看到所有账号。不设这道闸，他可以把任何员工的空间 收进自己名下，然后读里面的文件。这道闸防的是内部越权，不是外部攻击。

服务端强制：接收人必须在职（未停用/未过期/未删除）且不是原所有者；密级 ≥ 空间密级； 在该空间无显式拒绝（不静默清除 deny）；同一空间同时只能有一条待确认请求； 原所有者已停用/删除时，管理员不能转给自己，只能转给第三方。

6.3 一次移交改三处

位置含义

node.owner_id空间内原本属于原所有者的文件归谁（列表"归属"列）

三处必须同事务完成。只改前两处会出现"名字换了、权限没换"——比不移交更糟。 其他成员的文件归属、node 级别的单独授权、空间密级都不受影响。

6.4 空间台账

管理台 →「空间台账」（仅系统管理员）。列：空间名、所有者、授权条目、最近活动、状态、移交。

状态含义该做什么

7外发审批

7.1 什么时候需要审批

两个触发条件，满足任一即进入 pending：

  1. 创建链接时显式勾选「需要审批」；
  2. 对象密级 ≥ 租户阈值 share_approval_min_class（默认 3 = 秘密）。

创建时必须指定审批人：系统先枚举"对该对象有 manage_acl、密级足够、在职、不是发起人"的候选人，由发起人选择，服务端复核后落库。

为什么从"谁都能批"改成"指定一个人"：旧模型下多条链接同时 pending 时，所有合格审批人都以为别人会批，发起人也不知道在等谁。指派把责任落到具体的人。发起人只能在合格的人里挑，不能挑不合格的人；自批始终被拒。

没有合格候选人时，创建直接返回 409 NO_ELIGIBLE_APPROVER，不再生成永远 pending 的死链。

7.2 谁在审批

第一层：创建时指定的审批人，且必须仍满足下表条件。只有被指定的人能批——其他人即使有 manage_acl 也不能代批（403 NOT_DESIGNATED_APPROVER）。

条件说明
对该对象有 manage_acl空间「管理者」或「所有者」档位，或在文件 / 目录上单独授予过管理权限
密级 ≥ 文件密级密级先于权限：看不到的文件不可能审批
不是发起人本人自批返回 403 SELF_APPROVAL_DENIED

管理角色不等于审批权。系统管理员、安全管理员管的是配置（成员、密级定义、策略），不自动获得内容权限。所以"我是管理员，为什么看不到待审批"是正常现象——缺的是对象级 manage_acl，不是角色。

7.2.1 双层审批：再加一层所有者确认

是否加这一层由密级定义里该密级的「外发需所有者确认」决定（见 4.5，缺省 5/6 级）。

场景是否需要第二层
该密级未勾选「外发需所有者确认」不需要
已勾选，第一层审批人就是空间所有者不需要（同一人重复确认没有意义）
已勾选，第一层审批人是他人需要，由空间所有者确认
已勾选，发起人本人就是空间所有者不需要（发起即代表所有者知情，否则会变成自批）

所有者候选来自 space.owner_id 与空间上 preset=owner 的 ACE（含部门/角色/组展开），要求在职且密级 ≥ 对象密级。多个拥有者时，发起人在同一次分享里选一位。没有可用所有者且发起人不是所有者时，返回 409 OWNER_APPROVER_UNAVAILABLE。

两层一次选定、按顺序流转：pending(first) → 第一层通过 → pending(owner) → 所有者通过 → approved。任一层驳回即 rejected；第一层通过后链接仍不可用。

7.3 审批人从哪里操作

三个入口，看到的是同一份列表：工作台「等你处理」的待办、直接访问 /approvals （任何登录用户都可访问，不要求管理角色）、管理台「外发审批」 （/admin/share-approvals）。

第 2 条是关键：审批判据是对象级 manage_acl，而空间所有者通常不是管理员。 如果只有管理台有入口，这些人收到待办也点不进去，审批链会在最关键的一步断掉。

列表只显示当前轮到你的链接：第一层审批人看不到已经转给所有者的记录，所有者也不会在第一层通过前就看到它。每行给出文件、密级、发起人、当前环节、提交时间、链接有效期。

单层通过后链接立即可用；两层则进入 stage=owner，要等所有者确认。驳回在任何一层都直接 rejected。结果都写审计（share.approve，detail.decision 与 detail.stage）。

7.4 无人可批时怎么办

系统在创建前就会拦住并提示原因。按业务选一条路：

路线 1 · 推荐

给同事授权

发起人 → 文件 → 该空间 → 权限 → 添加成员 → 档位选「管理者」。该同事的密级也要 ≥ 文件密级。

路线 2

改由所有者审批

需要所有者确认且所有者密级不足时：先提密，或把第一层审批人改为空间所有者本人（此时只需一层）。

路线 3

降低文件密级

走降密审批，降到阈值以下后新链接不再需要审批。已 pending 的链接不会自动放行，需要重建。

如果这种情况反复出现，说明阈值（默认 3）对本租户偏低，或空间权限过度集中在单人手里。前者调 share_approval_min_class，后者应治理授权结构——不要用"关掉审批"来解决。

7.5 当前约束（需知）

  • 没有通知：待审批不会主动提醒任何人，发起人与审批人都要靠"自己去看列表"。两层之间转给所有者时也不推送，建议发起人另行告知。
  • 指定后不能换人：要换审批人只能撤销重建，审核中途不能改指派。
  • 一人一票，不能改判：通过或驳回之后不能再改，只能重新建链。
  • 审计写不进就拒绝操作：审批先改状态、再写审计；审计失败返回 500 并提示。此前的缺陷是审计 result 写了 approved（不在 ok/denied/error 约束内），导致审批一提交就 500，而状态其实已改——现已修正为 ok + detail.decision。

7.6 空间级外链的额外闸门

对空间生成外链时，若空间内存在：密级高于发起人的节点，或带显式拒绝条目的节点，直接拒绝（403 SPACE_NOT_SHAREABLE）。

这道闸门是刻意的：空间级外链面向匿名访客，子树的任何例外都会被绕过。遇到这个提示，正确做法是改为分享具体文件 / 目录，而不是让管理员去删例外配置。

7.7 下载 / 保存 / 打印

创建外链时有三个独立开关，决定访客能对文件做什么：

开关落库字段关闭时的行为
允许下载原件share.allow_download下载接口 403；不显示「下载原件」
允许保存在线副本share.allow_save不显示「保存副本」；屏蔽右键另存、Ctrl+S；图片改为画布呈现
允许打印share.allow_print不显示打印按钮；拦截 Ctrl+P；打印输出空白

约束：allow_save=false 时 allow_download 必须为 false——库里用 CHECK 约束（share_save_implies_no_download）挡住，接口也会先拒一次。理由：下载本身就是保存。

存量链接：迁移 0048 把两个新字段回填成与 allow_download 相同，所以以前的"只读"链接升级后仍是只读，并且不再能通过浏览器 PDF 工具栏下载。

修复的真实缺陷：只设 allowDownload=false 的分享，访客打开 PDF 后仍能下载。根因不在下载接口，而在呈现方式——PDF 放进 <iframe src=...>，浏览器自带阅读器的工具栏就带「下载 / 打印」。现在改用 pdf.js 把每页画到 canvas，页面内不再有原生保存入口。

边界：前端能挡"顺手保存"；截图、拍屏、开发者工具无法阻止。强管控靠：不外发、水印、访问记录。

7.8 访问记录：谁打开过我的链接

入口：左侧 我的分享（所有登录用户可见，不需要管理角色）。这一页回答三个问题：链接有没有被打开、从哪来、最近一次是什么时候。

动作记不记可信度
打开链接（兑换票据）✅服务端记录，准确
在线预览（含 Office 转 PDF）✅服务端在取内容时记录，准确

明细每行包含：时间、动作、IP、可见范围（内网 / 公网 / 本机）、归属地（需配置 IP 库）、浏览器与操作系统（由浏览器上报）。同一条链接出现 3 个及以上不同 IP 时标红「疑似被转发」——阈值偏低是刻意的，外发场景里多人用同一链接通常就是转发。

主机名与电脑登录用户名拿不到。浏览器沙箱不提供，任何网页都不提供，这不是本系统的缺陷。可行的替代：让对方用 SSO 登录（拿到真实账号）、开邮箱验证（拿到邮箱）、开水印（截图可溯源）；企业版如需主机名，只能装终端代理，属单独立项。

IP 归属地需要 IP 库：配置 DOCVAULT_GEOIP_DB（GeoLite2 / GeoIP2 的 .mmdb）后生效；未配置时只显示"内网 / 公网"，缺库不影响启动。

隐私：访问记录里的 IP 属于个人信息。外发邮件正文底部会自动附上隐私说明，并在配置了「隐私政策链接」时给出完整条款（见 3.8）。

  • 口令只提交、不回存明文，界面也不回显。开通成功后弹窗换成一张交付清单（系统地址 / 组织标识 / 管理员账号 / 口令说明），可一键复制直接发给客户。
  • 提交按钮固定在弹窗底部，字段区可滚动；口令在字段区下方，记得往下滚——这是此前最容易漏填的一项。
  • 开通时就把口令记录下来并当场转交：这是唯一一次能看到"自己要交什么"的时刻。线上出过一次"账号在、权限在，但没人知道口令"，最后只能走 §11.6 的运维通道重置。

客户还要再加管理员（租户内操作，平台侧不做）：

场景路径
新建一个管理员系统设置 → 用户管理 → 新建成员，「初始角色」选「系统管理员」
把已有成员提升成员行尾「更多操作」→「授予「系统管理员」」
撤销某人的管理员点其「角色」列上的 sysadmin ×

两条保护（服务端强制，不是界面提示）：不能撤销、停用或删除最后一个可登录的系统管理员，避免一次误操作把租户永久锁在管理入口外。三权分立：审计管理员不能与系统/安全管理员并存。

平台侧不提供"重置租户管理员口令"：那等于平台可以接管任何客户账号。客户忘掉唯一管理员的密码时，先走客户方其他管理员重置；一家都没有时属于运维介入（见 §11 的数据库操作），并应留下书面记录。

10.1 能力授权：给一个租户单独加购或收回

入口：平台运营台 → 能力授权 → 选一个租户（地址形如 /platform/entitlements/<租户标识>）。这一页存在的理由：客户可以只买一项，不必整档升级。

层在哪改回答的问题
档位（基础/专业/旗舰）「租户」页签 → 改档位这家客户买了哪一档
授权覆盖「能力授权」页签这一项单独给他开 / 关（加购、试用、合规下线）
灰度开关「灰度开关」页签这个功能全平台放不放（与客户买没买无关）

生效判断是三者同时成立：授权 ∧ 租户开关 ∧ 资源就绪。所以"运营开了但用户用不了"，按「授权 → 租户开关 → 资源就绪」的顺序查。

表格怎么读：基础/专业/旗舰三列是档位默认值（只读，要改默认值请改档位定义）；「当前」显示 跟随档位（含/不含）、已开通、已关闭、平台强制关闭，过期会标「（已过期）」；「到期」显示剩余天数，15 天内标黄， 开通时若不填到期日，默认 90 天（避免"忘了设到期"变成永久白送）。

三条操作纪律

  1. 「跟随档位」= 删掉覆盖，立刻回到档位默认。收回临时开通时用它，不要用「关闭」——关闭会留下一条 off 覆盖，客户以后升级档位也拿不到这一项。
  2. 「关闭」是显式拒绝，优先级高于档位。用于"这个客户不该有"的场景。
  3. 每次变更都进平台审计（platform.entitlement.set），带改前/改后；客户问"为什么没了"，按审计时间能对上。

常见误解：①「灰度开关里开了，为什么这家还不能用」——灰度是全局放量，授权是单客户购买，两回事； ②「档位里有这项，为什么还要授权」——档位是默认值，授权用来做"基础版单买一项"或"旗舰版临时收回某项"； ③「过期了是不是自动停」——是，过期覆盖按"没有覆盖"处理，回落到档位默认。

10.2 能力开关：全局、放量、租户覆盖（三级）

这是一处最容易互相误解的配置。2026-11 有过一次真实事故：平台把 share.external 的放量从 100 调到 0（总开关仍是"开启"），运营台显示"已开启"，而所有租户创建外链都收到"未开启对外分享能力，请联系平台运营"——运营进去看，每个开关都是开启的，找不到任何关闭动作。

求值顺序（固定，不可调换）：

租户覆盖（tenant_feature）> 全局总开关（default_enabled）> 放量（rollout_percent）
组合实际结果界面显示（现已修正）
总开关 开 + 放量 100%全部租户开启已开启
总开关 开 + 放量 25%约 25% 租户开启（按租户 ID 稳定分桶）已开启（放量 25%）
总开关 开 + 放量 0%全部租户关闭已暂停（并显示提示条）
总开关 关 + 放量任意除租户覆盖外全部关闭已关闭
有租户覆盖覆盖值优先，与全局无关本租户单独设置

放量 0% 是"暂停"而不是"没配"：它表达"功能已发布但当前不对任何租户开放"。因此界面不再把这种组合显示成"已开启"——那是这次事故的直接原因。

给单个客户开通（最常用）

  1. 运营台 →「租户」→ 点租户名 → 抽屉里找到「能力开关」；
  2. 每一行显示：能力说明、code、当前取值来源（跟随平台默认 / 平台放量 N% / 本租户单独设置）；
  3. 点「开通」写入租户覆盖；点「恢复默认」删除覆盖、回到平台策略。

这一步只改这一个租户，不动全局放量。合规交付里最常见的就是"平台默认全关，按合同逐个开"。

生效时间：开关有 30 秒缓存，改完 30 秒内全实例一致。急等不及可重启服务，但正常场景不必。

留痕：全局改动写 platform.flag.set，租户覆盖写 platform.flag.override（清除覆盖写 platform.flag.override.clear），都带操作人与新旧值，在「平台审计」可查。

四个开关的实际作用点

10.3 租户详情：一次看完一家客户

入口：平台运营台 → 租户 → 点租户名称（地址 /platform/tenants/<租户标识>）。详情是一整页，不是弹窗：左边是能改的东西，右边是只能看的信息。

位置内容能不能改
主列档位与到期、配额、自有域名与证书、按租户覆盖的功能开关可改（只读角色除外）
侧列概览、实时规模、租户最近操作、近 30 天用量只读

① 「导出对账单」导出的是本月 CSV，含"口径"列区分「当月累计」与「月末快照」。直接双击用 Excel 打开不会乱码（文件带 BOM）。

② 「租户最近操作」不会自动加载。平台每读一次，都会在客户自己的审计链里留一条「平台方读取过」的记录——这是刻意的可核查性设计：客户有权知道谁看过他的审计。所以只在排障时点一下「读取」；页面显示最近 20 条，要看全量请让客户在自己的「管理 → 日志」里查。

③ 域名证书有两条路：租户可在自己的「管理台 → 域名与证书」上传或自动签发；运营也可在这里代为上传（适合客户把证书发给你、但不会操作）。未验证归属的域名不能上传证书——先让客户配好 TXT 记录并点「验证归属」。

④ 「设为只读」不是"温和的停用"：成员仍能登录、仍能下载，但所有写入（上传、新建、改权限）会被服务端拒绝。客户很可能把这当成故障来报，操作前请先告知。

⑤ 改档与改配额都会立即生效，不需要客户重新登录。到期日留空表示不限期；降档时若存量数据无法被目标档位表达（例如有高档位密级），服务端会拒绝并返回受影响清单，不会"先降后报错"。

10.4 调整系统管理员密级（V1.7.0）

为什么放在运营台：密级有"不能授出高于自己"的硬规则，而开通、升档、或客户把管理员降到 0 级之后，租户里可能没有任何人能把管理员提回去。没有这个入口，只剩运维改库——不可审计、不可追责。

位置：租户详情页 → 「系统管理员密级」卡片。下拉只列本档位允许的密级（基础版只有 0；专业版 0/3/4；旗舰版 0–6），选好后点「保存密级」，可填一行调整原因。

能做不能做
改系统管理员的密级改普通成员的密级（那是租户管理员的事）
在档位允许范围内升降超出档位（基础版设 3 级会被拒 FEATURE_NOT_ENABLED）
留调整原因，平台与租户两侧都写审计重置口令、改角色、看客户文件（平台没有租户数据通道）

审计：平台侧记 platform.admin.classification，租户侧记 admin.member.classification（含改前 / 改后、操作者、原因）。客户在自己的审计里能看到"平台在什么时候把谁提到了几级"。

建议：只在上面的死锁场景使用；客户能自己解决时不要代劳——平台每次介入都会在客户审计里留痕。

11.3 铁律：镜像与迁移必须同批

  • 旧镜像 + 新库：可能因新增列 / 函数缺失而报错；
  • 新镜像 + 旧库：启动时自动迁移，正常；
  • 单独回滚镜像而不回滚库：如果迁移删过东西，会坏。

迁移文件的纪律：已有函数改签名要 DROP + CREATE，返回列只在末尾追加。这样旧镜像回滚到新库时仍能跑。

11.6 唯一管理员口令丢失（运维救援通道）

什么时候会用到：某家租户唯一的系统管理员口令丢了；该账号又没登记邮箱/手机，登录页的「忘记口令」走不通；平台运营台刻意不提供重置客户口令的能力（那等于平台可以接管任何客户账号）。此时只能由运维在服务器上处理。

工具：cmd/tenantpass（不进镜像，用源码或单独编译的二进制运行）。

cd /path/to/NeuroDMS
set -a; . docker/.env; set +a
export DOCVAULT_DB_DSN="postgres://${POSTGRES_USER}:${POSTGRES_PASSWORD}@127.0.0.1:55433/${POSTGRES_DB}?sslmode=disable"

# 1) 先看这家租户有哪些管理员（默认 dry-run，不改任何数据）
go run ./cmd/tenantpass -slug <租户标识>

# 2) 确认无误后再重置（生成 20 位随机口令，只显示这一次）
go run ./cmd/tenantpass -slug <租户标识> -apply -reason "工单 TCK-1234"

# 有多个可登录管理员时，必须用 -user 指定
go run ./cmd/tenantpass -slug <租户标识> -user admin -apply

# 改密级（V1.6.0）：升档后没人能提密级、或降档前清理成员密级
go run ./cmd/tenantpass -slug <租户标识> -user admin -setclass 6 -apply -reason "工单 TCK-1234"

它做了什么：改口令 + session_epoch 自增 + 吊销该账号全部会话，并在同一事务里写审计 admin.member.password（detail.source=tenantpass，可带 reason）。任一步失败整体回滚，不会出现"改了口令没留痕"。

三条纪律：① 口令只出现在屏幕上（不写文件、不进日志、不进审计），执行前确认没有录屏/共享终端；② 执行后立刻把"登录地址 + 组织标识 + 口令"转交客户，并要求客户登录后在「账号与安全」立即修改；③ 保留输出作为书面记录，用 -reason 写工单号，便于与审计对上。

-setclass N 把指定账号的密级改为 N（0–6），同时把 ceiling 抬到不低于 N，并在同一事务里写审计 admin.member.classification（含改前/改后）。优先用运营台的「系统管理员密级」卡片（§10.4），命令行只作为服务器侧兜底。

它不做的事：不创建账号（租户里一个管理员都不存在时，需要开发按现场数据补齐）；不解除停用/过期状态（账号不可登录时先恢复账号，工具会明确拒绝）。

11.7 部署加固基线

安全审查（docs/57）后固定下来的运行配置，改动前请先读这一节：

项值为什么
容器用户docvault（非 root）容器内进程被拿下也拿不到 root
no-new-privilegestrue阻断 setuid 提权
cap_dropALL服务不需要任何 Linux capability
根文件系统read_only: true后门无法在镜像层持久化
可写目录/tmp(512m)、/data/rawcache(1g) tmpfs；其余为数据卷只读根下必须显式声明写路径
端口绑定全部 127.0.0.1公网入口只有 Cloudflare Tunnel

只读根的两个坑：① 新增任何"会写文件"的功能，必须同时给卷或 tmpfs，否则启动日志里只有一句 read-only file system 并把该功能静默降级（RAW 预览就是这样消失的）；② 需要保留的文件不能放 tmpfs（重启即清空），只能放数据卷。

HSTS 依赖 X-Forwarded-Proto：TLS 在 Cloudflare 终止，应用收到的永远是 http。若换成不经代理的直连部署，这条头会自然停发（浏览器本就忽略 http 响应里的 HSTS），不需要改代码。

探测路径返回 404：/.env、/.git/config 这类带点或带扩展名的路径不再回退首页。SPA 路由约定是无扩展名的纯标识段（/files/<uuid>、/s/<token>），新增路由请遵守。

两字段模板的实例（公共模板「业务审批通知」：thing1 月度计划名称 / thing2 温馨提示）： DOCVAULT_WX_TODO_FIELDS=thing1=name,thing2=summary。 summary 的值形如「张三 · 待审批」，一个字段同时表达"谁发起"与"什么状态"； thing 类型限 20 字，过长按字段类型截断。

字段名可配置：你选的模板字段若不是上面四个，用 DOCVAULT_WX_TODO_FIELDS=字段名=语义键,… 声明映射（语义键只有 name / requester / time / status）。 写错（缺等号、键拼错、同一语义用两次）服务会拒绝启动并打印原因，避免"授权成功却收不到"。

小程序源码随主仓库发版（miniprogram/），调的是同一套接口。以下四项缺一项就有明确后果：

项在哪配不配的后果
request / downloadFile 合法域名微信公众平台 → 开发管理 → 服务器域名真机所有请求被拒（工具可关校验，真机不能）
DOCVAULT_WX_APPID / _APPSECRET服务端环境变量换不到 openid；/v1/mp/config 返回 enabled=false
DOCVAULT_WX_TODO_TEMPLATE同上（订阅消息模板 ID）提醒入口整体不显示（不是"点了报错"）
订阅消息模板字段微信公众平台 → 订阅消息字段不匹配微信返回 47003，提醒发不出（业务不受影响）
默认模板字段含义（语义键）示例
thing1文件名称（语义键 name；≤20 字截断）2026 年度采购合同

数据内容说明
app_user.mp_openid微信 openid 与绑定时间只存 openid，不存 session_key（用不到，存了只是多一个泄漏后果）
mp_subscription.remaining某账号某模板的提醒余额一次性订阅：发一条减一；上限 10，防止当成长期授权
审计 mp.bind / mp.subscribe谁在什么时候绑了微信 / 授权了几条openid 只在 detail 里留前 6 位

排障三步：用该账号调 GET /v1/mp/config，看 enabled / openidBound / remaining 三个值即可定位——没配置、没绑微信、还是额度用完。

通知失败不影响审批：分享创建成功即落库，提醒在后台发送，失败只记日志 （小程序审批提醒失败）。不要因为提醒没发出去就重建分享。
