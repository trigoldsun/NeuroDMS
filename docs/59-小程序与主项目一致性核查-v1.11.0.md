## 3. 五项不一致：根因与改法

### 3.1 合法域名未登记（阻断，真机无法请求）

**现象**：开发者工具里登录一律报"网络不可用，请检查网络后重试"；把 `urlCheck` 关掉立刻正常。
真机没有"不校验合法域名"这个开关，因此**真机上所有请求都会被拒**。

**根因**：`request` / `downloadFile` 合法域名未在微信公众平台登记（README 里"已登记"是声明，不是事实）。

**改法**：
- `project.config.json` 保持 `urlCheck: true`——让"域名没登记"在工具里就红，而不是等到真机；
- 本地开发改用 `project.private.config.json`（已 gitignore）临时关闭；
- 门禁 `scripts/check-miniprogram.mjs` 断言 `urlCheck === true`；
- README 第 1 节把这条写成"发布前置条件"，并明确"工具能绕、真机不能"。

**待办（运营动作，不是代码）**：在小程序后台登记 `ndms.neurongene.cn` 到 request 与 downloadFile，
然后用 `docs/screenshots/mp-preview-qr-1.11.0.jpg` 扫码复验真机。

### 3.2 MFA 账号"假成功"（阻断特定账号登录）

**现象**：账号开了二次验证时，口令登录返回 **202 + challenge**（无令牌）。小程序把 2xx 一律当成功：
保存空令牌 → 紧接着 `/v1/me` 401 → 界面提示"登录已过期"。用户看到的原因与事实完全无关。

**根因**：`utils/request.js` 用 `statusCode >= 200 && < 300` 判成功，没有识别 202 的语义。

**改法**：
- `request()` 遇到 `202 + data.mfaRequired` 抛 `ApiError('MFA_REQUIRED')`，并把 `challenge/sentTo/expiresIn`
  挂在 `err.mfa` 上；
- 登录页新增二次验证步骤：显示掩码邮箱与剩余有效期，输 6 位码后调 `POST /v1/auth/mfa/verify` 换令牌，
  支持"换一种方式登录"回退；
- 单测钉住：`scripts/test.js` 断言 202 不 resolve 且 `code === 'MFA_REQUIRED'`。

**证据**：`utils/request.js`、`pages/login/login.js|wxml`、`scripts/test.js`；
接口侧 `scripts/e2e/miniprogram.mjs` MP16/MP17（无邮箱时 fail-closed、伪造挑战不能换令牌）。

### 3.3 密级名称写死

**现象**：`utils/classify.js` 固定 7 档中文名。租户在「密级定义」里改名后，同一个人在网页端看到
"商密A"，在小程序里看到"秘密"。

**改法**：名称改由 `GET /v1/classifications` 提供并缓存（`utils/classify.js` + `services/meta.js`）；
取不到时**只显示"N 级"**，不编造名称；门禁禁止在小程序源码里出现密级中文字面量。

### 3.4 品牌未跟随租户

**现象**：`navigationBarTitleText` 固定"文档中心"，登录页品牌也是固定文案。主项目 1.7.1 已把
"图标 / 名称 / 标题"三要素统一到租户，小程序是唯一还显示厂商通用名的地方。

**改法**：
- `services/meta.js` 拉 `/v1/tenant/branding?slug=`，缓存 `productName`；
- 每页 `onShow` 调 `meta.applyTitle('文件'/'审批'/...)`，标题形如「森莘创新 · 文件」；
- 登录页品牌用缓存值；**未登录时无法知道租户**（同一域名多租户），所以只显示产品兜底名
  `config.PRODUCT_FALLBACK`，登录成功后立即覆盖；
- 门禁断言：`app.json` 标题 = `PRODUCT_FALLBACK`，且每个页面都调了 `applyTitle`。

### 3.5 审批阶段判了不存在的值

**现象**：`stageLabel` 判 `'approver'`，而数据库约束只允许 `none|first|owner|done`。
结果是首段一律显示"审批中"，本应是"待审批人处理"。

**改法**：按四个真实值映射，未知值显示"—"（不编造）。UI 自动化直接断言文案为"待审批人处理"。

## 4. 治理：让"以后还会漂移"不再可能

| 缺口 | 处理 |
|---|---|
| 源码不在主仓库 | 收入 `miniprogram/`，作为**唯一可信源**；工具直接打开该目录 |
| 版本号独立（2.0.0 vs 1.8.0） | `utils/config.js` 的 `VERSION` = 产品 `VERSION`，门禁校验相等 |
| 没有任何门禁 | 新增 `scripts/check-miniprogram.mjs`，挂进 `scripts/check.sh`；CI（`.github/workflows/check.yml`）跑全部门禁 |
| 只有静态自检 | 新增 `miniprogram/scripts/test.js`（202→MFA、密级名称、阶段枚举、格式化） |
| 真机链路没跑过 | 新增 `scripts/e2e/miniprogram.mjs`（接口）与 `scripts/e2e/mp-ui.mjs`（页面） |

门禁检查清单（`check-miniprogram.mjs`）：
1. 版本 = 产品 `VERSION`；
2. 每个 `/v1` 调用在后端路由表里存在；
3. 源码里没有写死的密级名称（注释除外）；
4. 阶段只认 `none|first|owner|done`；
5. 每个页面都有 `applyTitle`（标题跟随品牌）；
6. `urlCheck` 保持开启；
7. 顺带跑 `check.js` 与 `test.js`。

## 5. 新增能力（移动端高价值三件 + 一处识别）

| 功能 | 实现 | 边界 |
|---|---|---|
| **全文搜索** | `pages/search`：300ms 防抖、请求序号丢弃过期结果、区分"无结果/被截断" | 只返回有权查看的文件（服务端逐条判可见性）；目录结果不下钻，给明确提示 |
| **最近访问** | 文件页顶部横向卡片，取 `GET /v1/me/activity` 去重前 5 条 | 只在根目录显示；取不到静默隐藏，不让整页变错误态 |
| **审批提醒** | 微信订阅消息：`POST /v1/mp/bind`（code→openid）、`POST /v1/mp/subscribe`（余额 +1）、分享创建时后台发一条 | **一次性订阅**：授权一次发一条，余额存 `mp_subscription`；未配置通道时入口不渲染 |
| MFA 识别与引导 | 见 §3.2 | 验证码走**邮箱**（服务端 `startMFA` 用邮件通道，不是短信） |

后端新增（`internal/mpmsg`，迁移 0059）：
- access_token 缓存（提前 120s 过期）、发送失败如实返回错误码、余额原子扣减；
- 通知在**后台**发送：分享已经落库，通知失败不回滚业务，只记日志；
- 单测用假微信服务证明报文形状（`touser/template_id/page/data`）、token 只取一次、余额递减、
  未配置时零外呼。

## 6. 验收记录

### 6.1 接口链路（18 条，18/18）

从平台开通临时租户开始，回放小程序逐页发出的请求：登录（`channel=mp`）/ `/v1/me` / 密级定义 /
品牌 / 空间目录文件 / 元信息 / 预览 / 搜索 / 待办 / 审批 / 刷新与退出 / MFA 两种拒绝路径 /
提醒能力开关。

关键断言：
- `phoneMasked` 形如 `138****8000`、`phoneVerified=true`、首管理员密级 = 档位上限 6；
- 列表 `items` 永远是数组；`stage` ∈ `none|first|owner|done`；
- 预览返回正文且写入审计（`/v1/me/activity` 能查到该文件）；
- 未配置微信通道时 `/v1/mp/config` → `enabled=false`，`POST /v1/mp/bind` → **501 NOT_CONFIGURED**（不静默成功）。

### 6.2 页面链路（20 条，20/20，开发者工具真实渲染）

登录 → 文件页（搜索入口/最近访问/列表）→ 搜索（输入→结果→进预览→返回）→ 目录→文件→预览 →
最近访问出现 → 待办（阶段文案正确、无提醒入口）→ 审批详情 → 通过 → 待办清空 → 我的 →
退出回登录页 → 控制台零错误。

### 6.3 主项目回归

`scripts/e2e/run.mjs` 47/47。新增迁移 0059 与 `mpmsg` 未影响既有链路。

### 6.4 真机

**本轮未完成真机点击验证**，因为 §3.1 的域名登记是前置条件（不登记，真机一律请求失败）。

## 8. 复现步骤

```bash
# 1. 接口链路（自建临时租户，结束自动删除）
node scripts/e2e/miniprogram.mjs

# 2. 准备一份可人工/自动化点击的数据（保留租户并打印账号）
node scripts/e2e/miniprogram.mjs --prepare
#   → slug=mpxxxxx  account=admin@mpxxxxx  password=mp-pass-12345

# 3. 页面链路（需开发者工具已登录）
"<微信开发者工具>/cli.bat" auto --project <repo>/miniprogram --auto-port 9420
mkdir -p /tmp/mpui && cd /tmp/mpui && npm i miniprogram-automator
cd /tmp/mpui && MP_ACCOUNT=admin@mpxxxxx MP_PASSWORD=mp-pass-12345 node <repo>/scripts/e2e/mp-ui.mjs

# 4. 清理
node scripts/e2e/miniprogram.mjs --drop mpxxxxx

# 5. 门禁
node scripts/check-miniprogram.mjs
```

> 手机号验证状态由 `--prepare`/`--` 直接在测试租户里标记（真实流程是收短信，自动化收不到）。
> 这条旁路只存在于测试脚本，不在任何业务代码里。
