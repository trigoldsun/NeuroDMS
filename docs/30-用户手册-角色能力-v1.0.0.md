配套文档：`29-用户手册-场景操作`、`31-管理员手册`

## 0. 三层身份，不要混为一谈

大多数人第一次用会困惑"我到底是什么角色"。系统里有**三套彼此独立的维度**：

| 维度 | 回答的问题 | 谁设置 | 例子 |
|---|---|---|---|
| **账号类型** | 你是不是本组织的人 | 系统管理员 | 内部成员 / 外部协作者 |
| **管理角色** | 你能否进入管理台、能改什么配置 | 系统管理员 | 系统管理员 / 安全管理员 / 审计管理员 |
| **权限档位** | 你对**某一个文件/空间**能做什么 | 对象所有者 | 查看者 … 所有者 |
| **密级** | 你能接触多敏感的内容 | 安全管理员 | 公开 … 核心 |

一个常见的误解：「我是系统管理员，所以我能看所有文件」——**不能**。管理角色管的是**配置**，不是**内容**。系统管理员默认看不到别人空间里的文件，除非被显式授权。

反过来也成立：文件所有者拥有全部内容权限，但进不了管理台。

## 2. 五个内容档位：逐档说明

### 2.1 查看者（viewer）

**能做的场景**：查看目录结构、在线预览文件、看版本列表。

**不能做但常被期待的事**：
- 不能下载（预览是"看"，不是"取走"）；
- 不能复制正文——复制属于 `copy` 位，查看者没有；
- 不能分享。

**为什么预览和下载要分开**：很多合规要求是"可以看、不能带走"。把它们合成一个开关，就没法表达这条策略。

**给谁**：外部评审、只读旁听、跨部门知会。

### 2.2 贡献者（contributor）

**在查看者基础上加**：下载、打印、上传。

**典型场景**：让各部门往一个目录里交材料，但不许他们互相删改。

**注意**：贡献者能上传，因此也能**覆盖同名文件**（产生新版本）。要防止覆盖，就别给上传位，改为"由一个人统一收口"。

### 2.3 编辑者（editor）

**在贡献者基础上加**：在线编辑、复制、改名。

**典型场景**：一起改一份方案。

**注意**：
- 改名与改内容是**两个位**（`rename` / `edit`）。当前版本的"改名"按 `rename` 判定，所以只给 `edit` 的人改不了名——需要同时给。
- 编辑会登记"编辑会话"，会影响别人回退版本（见场景 4）。

### 2.4 管理者（manager）

**在编辑者基础上加**：移动、删除、内部分享、版本管理。

**典型场景**：项目负责人整理目录、清理过期材料、把文件分享给项目组。

**注意**：
- 管理者能**内部分享**但不能**外发**。这是有意的分界：内部扩散的风险远低于全互联网可见。
- 管理者能删除，但删除是软删除（进回收站），不是立刻销毁。

### 2.5 所有者（owner）

**全部能力**，并且独有：
- 给别人授权（`manage_acl`）；
- 生成外发链接（`share_external`）；
- 移交所有权。

**注意**：
- 一个对象**至少要有一个所有者**，系统拒绝移除最后一个；
- 授权时不能授出高于自身封顶（`ceiling`）的档位。默认封顶是最高档，所以"所有者能授出所有者"是正常行为，不是漏洞；
- 所有者被停用后，其所有权条目仍在——**离职必须先移交**（见场景 7）。

## 3. 外部协作者（external）

**是什么**：在本租户内、但标记为外部的人员账号。用来给长期合作方开账号，而不是发链接。

**默认限制**：
- 创建时**强制二次验证**（邮箱验证码）。收不到码就登不上，这是 fail-closed 行为；
- 外部主体只能通过 `external:` 前缀的授权条目获得权限，**不会**因为"同部门"自动继承内部授权；
- 外部账号无法成为空间所有者以外的高级档位？——不，档位本身不限，但密级与授权范围要单独给。

**给谁**：长期驻场的供应商、外部财务顾问。

**与"外链"的选择**：

| | 外部协作者账号 | 外链 |
|---|---|---|
| 适合 | 长期、频繁、需要留痕到人 | 一次性、临时、对方不愿注册 |
| 追溯 | 精确到账号 | 精确到链接 + 网段 + 时间 |
| 回收 | 停用账号 | 撤销链接 |
| 成本 | 占席位 | 不占席位 |

## 4. 三个管理角色

### 4.1 系统管理员（sysadmin）

**管什么**：人、组织、系统参数。

| 场景 | 入口 | 说明 |
|---|---|---|
| 建号 / 停用 / 删除 | 管理台 → 成员与角色 | 停用立即吊销会话，30 秒内生效 |
| 分配管理角色 | 同上 | **不能给自己加冲突角色**（见 §5） |
| 重置他人密码 | 同上 | 重置后对方全部会话失效 |
| 改租户策略 | 管理台 → 系统设置 | 上传上限、超时、日志保留、格式白名单 |
| 配目录认证 | 管理台 → 目录认证 | LDAP/AD、SSO 断言 |
| 看操作日志 | 管理台 → 操作日志 | 业务流水，可按人/对象筛 |

**不能做**：
- 看不到别人空间里的文件（管理角色 ≠ 内容权限）；
- 改不了密级定义与标签策略（属安全管理员）；
- 看不到审计日志（属审计管理员）。

### 4.2 安全管理员（secadmin）

**管什么**：密级、标签、降密审批。

| 场景 | 入口 | 说明 |
|---|---|---|
| 改密级显示名与描述 | 管理台 → 密级定义 | **只能改名称与描述，等级数值固定**。改数值会让历史数据语义翻转 |
| 配标签策略 | 管理台 → 标签策略 | 给带某标签的文件设最低密级（只收紧，不放松） |
| 审批降密申请 | 管理台 → 降密审批 | 通过后文件密级下调 |
| 审批外发链接 | 无页面，走接口 | 且必须对该对象有 `manage_acl` |

**不能做**：建号、改系统参数、看审计日志。

**常被误解的一点**：安全管理员**没有**"绕过密级"的特权。系统刻意不给安全管理员豁免——否则"高密文件外发必须有人复核"就形同虚设。

### 4.3 审计管理员（auditor）

**管什么**：只读审计。

| 场景 | 入口 | 说明 |
|---|---|---|
| 查审计事件 | 管理台 → 审计日志 | 含成功与失败，含被拒绝的越权尝试 |
| 校验审计完整性 | 同上 → 校验 | 校验哈希链，判断记录是否被篡改 |
| 导出证据包 | 同上 → 导出 CSV | 用于内审/外审取证 |

**不能做**：任何写操作。审计管理员看不到"删除审计"按钮，因为不存在。

**为什么审计管理员不能是系统管理员**：能改配置的人如果能同时读/改审计，独立性就没了。系统的三权分立检查会在**运行期**拦住同时持有冲突角色的账号——不是只在界面上隐藏。

## 5. 三权分立：哪些角色组合被禁止

| 组合 | 结果 | 原因 |
|---|---|---|
| 系统管理员 + 审计管理员 | 拒绝（`SEPARATION_VIOLATION`） | 能改配置又能改审计 = 无独立审计 |
| 系统管理员 + 安全管理员 | 允许 | 小团队常见，职责可合并 |
| 安全管理员 + 审计管理员 | 拒绝 | 能改密级又能审自己 |
| 三个全给 | 拒绝 | 同上 |

被拒绝时不是"按钮消失"，而是**所有管理接口都返回 403 并写审计**。也就是说，一旦配错，这个账号会立刻失去全部管理能力——这是刻意的强约束，配错时要尽快改回来。

## 6. 平台运营（仅 SaaS 形态）

平台账号与租户账号**完全分离**：不同的表、不同的令牌、不同的入口（`/platform/{tab}`）。

| 能力 | 说明 |
|---|---|
| 租户生命周期 | 新建、停用、逻辑删除；停用后该租户所有人立即不可用 |
| 配额与档位 | 调整存储/席位/上传上限；改档位立即生效 |
| 灰度开关 | 按租户关闭外发、邮件验证、音视频转码等能力 |
| 用量与对账 | 按租户看存储、API 调用、导出对账单 |
| 平台审计 | 平台侧的每一次操作都留痕 |

**边界**：平台运营**不能**读租户文件内容。平台能看到"这个租户用了多少、开了哪些开关"，看不到"里面存了什么"。这是多租户产品的信任前提。

**自托管/私有化部署**没有这一层，对应能力由本地系统管理员承担（且不含许可证管理，见部署说明）。

## 7. 典型 403/404 对照表

| 返回 | 含义 | 该找谁 |
|---|---|---|
| 403 `CEILING_EXCEEDED` | 想授出的档位高于自己的封顶 | 让更高档位的人授权 |
| 403 `SEPARATION_VIOLATION` | 角色组合冲突，管理能力被冻结 | 系统管理员调整角色 |
| 403 `FEATURE_DISABLED` | 平台/租户关掉了该能力（如对外分享） | 系统管理员或平台运营 |
| 403 `SELF_APPROVAL_DENIED` | 审批自己发起的分享 | 换一位审批人 |
| 403 `SPACE_NOT_SHAREABLE` | 空间含你无权访问或更高密级内容 | 改为分享具体文件/目录 |
| 403 `DOWNLOAD_FORBIDDEN` | 该外链不允许下载 | 让分享人开启下载 |
| 404 `NOT_FOUND` | 不存在**或**无权限（系统不区分） | 用权限解释确认 |
| 409 `INHERITED_ACE` | 想删继承来的权限条目 | 先恢复继承，再调整上层 |
| 400 `LAST_OWNER` | 想移除最后一个所有者 | 先给别人所有者档位 |
