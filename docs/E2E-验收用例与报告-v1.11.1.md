## 1. 目标与方法

**目标**：以"开通租户"为起点，沿真实 HTTP 接口走完一条完整的业务链路，
验证平台侧与租户侧的主流程、权限边界与安全约束，并把发现的问题与修复建议一次列清。

**方法**：

1. **只走公开接口**（不直连数据库、不改库）——测的是"客户拿到手能不能用"；
2. **每个用例独立断言 + 失败即停**：先定位根因，再决定修还是登记；
   修复后从失败点重跑（脚本从头跑，状态幂等）；
3. UI 侧用 Playwright（本机 Chrome）做冒烟：登录页 → 工作台 → 文件 → 管理台 → 退出；
4. 测试租户用独立 slug（`e2e*` / `ui*`），成功即删；失败保留现场供复跑，确认后删除。

**环境**：产品 V1.8.0，本地 `http://127.0.0.1:18090`（与公网同一镜像），PostgreSQL 18，迁移头 0058。

## 3. 发现项与修复（按严重度排序）

### F-03｜部门没有写接口，非 AD 租户无法自建组织结构（中）— ✅ 已修复

- **现象**：`GET /v1/admin/depts` 可读，但不存在 `POST/PATCH/DELETE /v1/admin/depts`；
  管理台也没有部门页。开通后只有一条「总部」，所有成员都挂在根部门下。
- **影响**：不接 AD 的租户无法按部门做批量授权（ACL 支持 `subjectType=dept`，
  但没有部门可授）；"按部门管权限"这个卖点在不接目录的客户那里用不上。
- **根因**：部门数据只由目录同步写入（`internal/directory`），没有把它当成租户内的一等对象设计。
- **建议**：补三个接口 + 管理台「部门」页（树形增删改、移动成员）；
  或明确"部门仅来自目录同步"，并在界面把"总部"标成"默认部门"。
- **工作量**：中（接口 + 权限 + 审计 + 前端树）。

### F-06｜公开桶限流 2 rps，连带影响**登录**与外链首屏（中→按 P1 处理）— ✅ 已修复

- **现象**：`DOCVAULT_PUBLIC_RATE_RPS=2`、`burst=10`；`/v1/auth/login`、
  `/v1/platform/auth/login`、`/v1/public/*` **共用同一个桶**（按客户端 IP 计数）。
  实测两处都会被误伤：
  1. 外链页首屏（兑现 + 票据 + 列表/缩略图）连发，几秒内就 429；
  2. **同一出口 IP 连续登录几次**（同一办公网 10 人同时登录即可）也会 429。
- **影响**：客户看到的是"请求过于频繁，请稍后再试"，而我们对外承诺的是"链接发出去就能看"、
  "上班时间大家同时登录没问题"。这是**可用性**问题，不是压力测试才出现的极端情况。
- **根因**：把"登录爆破防护"和"外链防枚举"塞进同一个低速率桶，且按 IP 而非"IP+用途"分桶；
  正常用户的多个合法请求被算成一次滥用。
- **建议**：① 登录单独一档（如 10 rps / burst 30，配合账号级锁定——锁定已按账号计）；
  ② `/v1/public/tickets/*` 放宽到 10–20 rps，或按票据计数；
  ③ `429` 响应已带 `Retry-After`，客户端应按它退避（本次脚本照此实现后连跑稳定）。
- **工作量**：小（改配置与分桶规则）/ 中（按票据计数）。

### F-01｜列表型字段返回 `null` 而非 `[]`（低）— ✅ 已修复

- **现象**：新建租户无用量时，`GET /tenants/{slug}/usage` 的 `points` 为 `null`；
  前端靠 `?? []` 兜住。
- **影响**：客户端必须逐个字段判空，否则 `points.map` 直接崩。
- **建议**：服务端统一返回空数组（一行改动），并在接口约定里写明"列表永不为 null"。
- **工作量**：极小。

### F-02｜能力授权"跟随档位"的表示不统一（低）— ✅ 已修复

- **现象**：`GET /entitlements` 用空字符串 `state:""` 表示"跟随档位"，
  而 `PUT` 要求传 `state:"inherit"`；传 `"default"` 直接 400。
- **影响**：对接方（含我们自己的脚本）必然踩一次；错误信息也不提示合法值。
- **建议**：GET 也返回 `"inherit"`，PUT 同时接受 `"default"`/`"inherit"` 作为别名；
  400 响应里列出允许值。
- **工作量**：小。

### F-04｜建空间类型非法时，错误信息不列可选值（低）— ✅ 已修复

- **现象**：`POST /v1/spaces {kind:"team"}` → `INVALID_ARGUMENT 空间类型或名称不合法`。
  合法值是 `personal / dept / project / knowledge / archive`，只能去读代码。
- **建议**：错误信息带上可选值，或在 `GET /v1/meta` 里暴露枚举。
- **工作量**：极小。

### F-05｜"需要口令"用 411 状态码（低，语义）— ✅ 已修复

- **现象**：分享链接需要口令时返回 `411 PASSWORD_REQUIRED`。
- **影响**：411 本意是"缺少 Content-Length"，网关/监控会判成畸形请求；
  而 401/403/428 才是"未提供凭据"的常规语义。
- **建议**：改 `428 Precondition Required`（保留 `PASSWORD_REQUIRED` 错误码，
  前端按 code 判断，兼容旧客户端）。
- **工作量**：小（但要同步改前端判断与文档）。

## 6. 复现方式

```bash
# 1) 准备：平台账号（docker/.env 里的 DOCVAULT_PLATFORM_ADMIN / _PASSWORD）
set -a; . docker/.env; set +a

# 2) 跑 47 条 API 用例（默认失败即停；--keep-going 可跑完全部）
PA_EMAIL="$DOCVAULT_PLATFORM_ADMIN" PA_PASS="$DOCVAULT_PLATFORM_ADMIN_PASSWORD" \
  node scripts/e2e/run.mjs

# 3) 失败时会保留测试租户（slug 会打印），确认后可手工删除：
#    curl -X DELETE -H "authorization: Bearer <平台令牌>" \
#      http://127.0.0.1:18090/v1/platform/tenants/<slug>
```

脚本本身不含凭据，全部从环境变量读；断言信息均为"期望 / 实际"两段，便于贴进工单。
