# NeuroDMS V1.0.0 · 正式版发布与回退手册

> 发布日：2026-11-13
> 适用：`ndms.neurongene.cn`（SaaS 发行物，多租户 + 平台运营台）

本版把此前 "开发中" 的形态收敛为第一个正式版本，并建立三重快照，保证任何一次后续改动都能退回本版。

## 三、日常发布

```bash
# 1) 先备份（发布前必须做）
TS=$(date +%Y%m%d-%H%M)
docker exec docvault-postgres sh -c "pg_dump -U docvault -d docvault -Fc -f /tmp/ndms-$TS.dump"
docker cp docvault-postgres:/tmp/ndms-$TS.dump docker/data/backup/

# 2) 构建并上线（镜像内含前端产物；启动时自动跑迁移）
cd docker
docker compose build server
docker compose up -d server

# 3) 验证
curl -fsS http://127.0.0.1:18090/readyz
curl -fsS https://ndms.neurongene.cn/ | grep -o '<title>[^<]*</title>'
```

## 四、回退到 V1.0.0

回退分三种情况，按"改了什么"选择，不要一律全回退。

### 4.1 只回退应用（代码/镜像），数据库不动

适用：新版本有功能缺陷，但没有不兼容的迁移。

```bash
cd docker
# 方式 A：把 compose 里的 image 临时指向版本标签
#   server.image: docvault/server:v1.0.0
docker compose up -d server

# 方式 B（不改文件）：把 dev 标签重新指回旧镜像
docker tag docvault/server:v1.0.0 docvault/server:dev
docker compose up -d server
```

> 注意：若新版本已应用了**破坏性迁移**（删列、改函数签名），仅回退镜像可能启动失败。
> 本仓库的约定是"迁移只追加、函数改签名用 DROP+CREATE、返回列只在末尾追加"，
> 因此绝大多数情况可以直接回退镜像；遇到结构不兼容才走 4.2。

### 4.2 应用 + 数据库一起回退（彻底回到发布时状态）

⚠️ 会丢弃发布之后产生的数据（新文件、新账号、新审计）。执行前必须确认。

```bash
cd docker
# 1) 停应用，避免写入
docker compose stop server

# 2) 恢复数据库（先确认容器内有这份 dump，必要时先 docker cp 进去）
docker cp data/backup/ndms-v1.0.0-20261113-2352.dump docvault-postgres:/tmp/restore.dump
docker exec docvault-postgres sh -c \
  "pg_restore -U docvault -d docvault --clean --if-exists --no-owner /tmp/restore.dump"

# 3) 用版本镜像启动
docker tag docvault/server:v1.0.0 docvault/server:dev
docker compose up -d server

# 4) 验证
curl -fsS http://127.0.0.1:18090/readyz
```

### 4.3 只回退源码（排查/二次开发）

```bash
git fetch --tags           # 若已配置远端
git checkout v1.0.0        # 或 git switch -c hotfix/v1.0.0 v1.0.0
cd web && npm ci && npm run build
```

源码快照不含 `web/node_modules`、`web/dist`、`docker/data`、`docker/.env`（含密钥，绝不入库）。

### 4.4 可选：镜像离线归档（防 `docker system prune` 清掉标签）

镜像 1.76 GB，含 LibreOffice 等运行时；只靠本地标签时，一次清理就可能丢失。
需要"离线可回退"时导出一次即可（约 1 GB，放在备份盘或对象存储）：

```bash
docker save docvault/server:v1.0.0 | gzip > docker/data/backup/neurodms-image-v1.0.0.tar.gz
# 恢复
gunzip -c docker/data/backup/neurodms-image-v1.0.0.tar.gz | docker load
```

日常不必导出：源码标签 + `docker compose build` 可以重建镜像，前提是能拉取基础镜像。

**本机推送注意事项**：这台机器上 `github.com` 的 DNS 被解析到不可达地址
（`20.247.166.64`），真机可用的 IP 是 `20.205.243.166` / `140.82.112.4`。
已在仓库本地配置解析覆盖（不随代码提交）：

```bash
git config --local http.curloptResolve "github.com:443:20.205.243.166"
```

若某天推送报 SSL/连接错误，先换一个可用 IP：

```bash
dig +short github.com @8.8.8.8        # 或 nslookup
git config --local http.curloptResolve "github.com:443:<新IP>"
```

更稳的做法是给账号加一把 SSH key，走 `ssh.github.com:443`（该主机在本机可直连）：

```bash
ssh-keygen -t ed25519 -C "neurodms"    # 已存在可跳过
cat ~/.ssh/id_ed25519.pub              # 贴到 GitHub → Settings → SSH keys
git remote set-url origin git@github.com:trigoldsun/NeuroDMS.git
git config --local core.sshCommand "ssh -p 443 -o HostName=ssh.github.com"
```

## 八、维护约定

- 每次发布前：`pg_dump` → 打 tag（`vX.Y.Z`）→ 打镜像标签 → 记录到本表。
- 迁移只追加，不修改已发布文件；函数改签名必须 `DROP FUNCTION` + `CREATE`。
- 发布后 24 小时内保留上一版镜像与 dump，不做清理。
- `docker/data/backup/` 下的 dump 属于灾备资产，**不要**提交进仓库（已在 `.gitignore`）。
