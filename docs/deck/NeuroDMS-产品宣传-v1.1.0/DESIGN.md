## 1. 品牌对齐（只取用得到的部分）

**色板**（8 支里用 6 支，青与紫仅作锐进调性的渐变，本 deck 未使用）：

| 槽位 | Hex | 用途 |
|---|---|---|
| 墨 INK | `#0A120E` | 深底、正文、锐进调性背景 |
| 纸 PAPER | `#F5F7F2` | 内容页底色 |
| 森绿 FOREST | `#0F5C40` | 主色：标题强调、编号、色块 |
| 芽绿 SPROUT | `#C6EE4B` | 单点强调：深底数字、关键色块、顶芽 |
| 石板 SLATE | `#66756D` | 次级文字、章节标注 |
| 雾 MIST | `#A9B5AE` | 页脚、占位、禁用 |
| 线 | `#DDE4DC` | 分割线、表格线 |

**面积比例**（品牌硬约束）：纸/白 ≥ 60%，墨 ≤ 25%，森绿 ≤ 12%，芽绿 ≤ 5%。
芽绿**不作浅底文字**——对比度不足 1.5:1；浅底上要强调就用森绿，或芽绿作色块底 + 墨字。

**双调性**：
- 封面、数字页、结尾用 Kinetic（墨底 + 芽绿 + 点阵阶梯）；
- 其余用 Quiet（纸底 + 细线 + 大留白）。
两档只在表皮分叉，几何与字体不变。

**图形母题**：点阵与阶梯。封面右上 9×9 点阵 + 五级阶梯；"共有能力"页用宽度递增的卡片做阶梯。
不用摄影图、不用 3D、不用图标墙——安全类产品靠结构与数据说话。

**字体**：中文思源黑体（`Source Han Sans SC`），回退微软雅黑；数字用同一字族的等宽特性。

**语气**（品牌三要三不要）：
- 要：具体数字与可验收事实；边界与"不含"；一句一结论。
- 不要：赋能/一体化/领先；无法证伪的形容词；编造 ROI 百分比。
- 本 deck 的所有数字都来自系统实测或配置默认值，页面上不出现"效率提升 X%"这类口径不明的说法。

## 4. 与 v1.0.0 的结构差异（为什么删了一页）

v1.0.0 有一页「一个实例，多个租户，互不可见」。这一版把它删掉，原因：
多租户是 **SaaS 的形态特征**，不是两条产品线共有的能力。放在功能中段会让本地部署客户
误以为"这套东西是给多租户设计的"。

它的三条论证（库内行级隔离、39 张表全覆盖、启动自检拒启）被并入第 10 页的「数据边界」行，
并保留一句"从订阅转为本地，权限与历史不需要重建"——这才是采购方真正关心的问题。

## 6. 交付与工程注意（踩过的坑）

**交付文件**：`NeuroDMS-产品宣传-v1.1.0-20261112.pptx`（14 页）。

**slidep 会在每页 `<p:sld>` 根元素之后追加整段 DSL 源码。** 这个尾巴让 slide XML
变成"根元素后还有文本"的非法文档，PowerPoint 打开会提示修复。虽然 `slidep screenshot`
仍能渲染，但它不是可交付的 PPTX。交付前必须做一步截断：

```python
text = xml.split('</p:sld>')[0] + '</p:sld>'
```

本次交付前已对 14 页全部截断，并用 `soffice --headless --convert-to pdf` 实际打开验证
（生成 544 KB / 14 页 PDF，说明结构合法）。**以后用 slidep 出片，这一步不能省。**

**`upsert-dsl` 不带 `--page-index` 是追加，不是替换。** 想改某一页必须显式传索引；
反复追加会让页数悄悄变多（本次一度出现 17 页）。更稳的做法是每次从空白文件重建：
`create` → 按 01…14 顺序 `upsert`。

**文件句柄**：slidep 渲染服务会持续持有 pptx 句柄，导致改名/删除失败（WinError 32）。
所以在同一目录里可能残留几个构建中间文件，交付以文件名带日期的那个为准。
